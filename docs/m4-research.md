# M4 — ปีศาจที่วางแผนได้ และเรียนรู้จากผู้เล่น (2026-10-08)

> สรุปสั้น: เพิ่ม **POMCP** (วางแผนบนความเชื่อ) และ **opponent model** (โมเดลว่าผู้เล่นเคลื่อนที่อย่างไร
> เรียนจากข้อมูล) ให้ปีศาจตาบอด ทดลองในตัวจำลองแล้วดีขึ้นอย่างมีนัยสำคัญ และสร้าง **telemetry + backend**
> ที่เก็บข้อมูลการเล่นจริงทุกคืน → ฝึกโมเดลใหม่ → ส่งกลับเข้าเกม

## 1. สิ่งที่สร้าง

| ส่วน | ไฟล์ | ทำอะไร |
|---|---|---|
| Opponent model | `src/shared/OpponentModel.luau` | ทำนายก้าวถัดไปของผู้เล่น จาก "ตอนนี้อยู่ห้อง/ตู้" × "ปีศาจห่างกี่ห้อง (0,1,2,3+)" → 8 บริบท × 6 ประเภทก้าว (อยู่นิ่ง, เข้าหา, หนี, ข้าง, เข้าตู้, ออกตู้) |
| POMCP | `src/shared/Pomcp.luau` | Monte Carlo tree search บนความเชื่อ: สุ่มสถานะจาก particle → UCB1 เลือก macro-action → จำลองผู้เล่นด้วย opponent model → rollout → backup รางวัลแบบ discount |
| สมองปีศาจ | `src/shared/HunterBrain.luau` | `rule` / `belief` / `pomcp` ใช้ particle filter ชุดเดียวกัน (ประสาทสัมผัสเท่ากัน เทียบได้ยุติธรรม) และรับ opponent model ได้ |
| โมเดลเริ่มต้น | `src/shared/DefaultModel.luau` | โมเดลที่ฝึกจากบอท 4 แบบ (54,003 ก้าว) ใช้จนกว่า backend จะมีโมเดลจากคนจริง |
| Telemetry | `src/server/Telemetry.luau` | บันทึก 1 record ต่อคืน (ตำแหน่งทุก 0.5 วิ, เหตุการณ์, ผล, เวลาคำนวณ) ส่งเป็นก้อนตอนจบคืน ไม่มี user id |
| ตารางปีศาจ | `src/server/Config.luau` | story: คืน 1–2 belief, 3–6 pomcp, 7 pomcp+model · experiment: สุ่ม 1 เงื่อนไขต่อรอบ (A/B playtest) |
| Backend | `backend/` | FastAPI + SQLAlchemy (SQLite/PostgreSQL), ฝึกโมเดลแบบ train/holdout, สถิติพร้อม CI, dashboard, 22 tests |

## 2. วิธีทดลอง (ตัวจำลอง)

- บ้าน 16 ห้อง, ผู้เล่นบอท 2 ตัว, คืนละ 180 วิ, รังปีศาจสุ่ม, ปีศาจตื่นหลัง 8 วิ, เดิน 13 / พุ่ง 18, การได้ยิน 0.9
- 100 คืนต่อแถว **ใช้ seed เดียวกันทุกสมอง** ความต่างจึงมาจากสมอง ไม่ใช่ดวง
- ตัวชี้วัดหลัก: catch% = สัดส่วนผู้เล่นที่ถูกจับ (ยิ่งสูง ปีศาจยิ่งเก่ง), first-catch = วินาทีที่จับคนแรกได้
- สถิติ: two-proportion z-test (`backend/app/stats.py`), n = 200 ผู้เล่นต่อแถว

## 3. ผล

### 3.1 วางแผน (POMCP) vs ไม่วางแผน — ยังไม่มี opponent model

| ผู้เล่นแบบ | rule | belief | **pomcp** | pomcp vs belief |
|---|---|---|---|---|
| hider (ซ่อนตู้) | 34.5% | 50.5% | **81.5%** | z = 6.54, p < 0.001 |
| decoy (ซ่อน + ปาของล่อ) | 41.5% | 47.5% | **73.5%** | z = 5.32, p < 0.001 |
| collector (เก็บลัง เสียงดัง) | 9.5% | 5.5% | **12.5%** | z = 2.45, p = 0.014 |
| wanderer (วิ่งมั่ว) | 99.5% | 99.5% | 98.0% | เพดาน: ทุกสมองจับได้ |

- POMCP แก้จุดอ่อนจาก M2 ได้: belief เคยแพ้ rule กับผู้เล่นเก็บลัง ตอนนี้ pomcp ชนะ belief อย่างมีนัยสำคัญ
  (แต่ pomcp vs rule กับ collector: 12.5% vs 9.5%, p = 0.34 **ยังไม่ต่างอย่างมีนัยสำคัญ**)
- เวลา: วางแผน ~5 ms ต่อครั้ง แต่วางแผนเฉพาะตอนปีศาจว่าง (~ทุก 2 วิ) → เฉลี่ย ~1.1 ms ต่อ tick

### 3.2 Opponent model ทำนายผู้เล่นได้ดีขึ้นไหม

ประเมินบนคืนที่ไม่ได้ใช้ฝึก (seed 9001+). LL = log-likelihood เฉลี่ยต่อก้าว (สูงกว่าดีกว่า),
acc = ทายห้อง/ตู้ถัดไปถูกเมื่อผู้เล่นขยับจริง

| ผู้เล่นแบบ | uniform (เดาสุ่ม) | learned (ฝึกจากแบบเดียวกัน) | **leave-one-out** (ไม่เคยเห็นแบบนี้) |
|---|---|---|---|
| hider | LL −0.325, acc 40.4% | LL −0.273, acc 56.1% | LL −0.288, acc 49.5% |
| collector | LL −0.583, acc 34.6% | LL −0.445, acc 61.2% | LL −0.544, acc 59.7% |
| decoy | LL −0.323, acc 40.8% | — | LL −0.293, acc 48.3% |
| wanderer | LL −0.967, acc 38.3% | LL −0.846, acc 46.5% | **LL −1.026, acc 33.3% (แย่กว่าเดาสุ่ม)** |

- อธิบายได้: เมื่อปีศาจอยู่ห้องติดกัน hider เข้าตู้ 57% ของ tick; เมื่ออยู่ห้องเดียวกัน หนี 42%
- **leave-one-out** = ฝึกจากบอทอีก 3 แบบ แล้วทดสอบกับแบบที่ไม่เคยเห็น (จำลอง "เจอผู้เล่นสไตล์ใหม่")
  ใช้ได้ 3 ใน 4 แบบ แต่ **wanderer ไม่ได้** เพราะพฤติกรรมต่างจากทุกแบบที่ฝึก → ข้อจำกัดที่ต้องเขียนในเล่ม

### 3.3 Opponent model ทำให้ปีศาจเก่งขึ้นไหม

| ผู้เล่นแบบ | pomcp | pomcp + model (ฝึกรวม 4 แบบ) | pomcp + model (leave-one-out) |
|---|---|---|---|
| hider | 81.5% | 96.0% (p < 0.001) | 95.0% (p < 0.001) |
| collector | 12.5% | 31.5% (p < 0.001) | 26.5% (p < 0.001) |
| decoy | 73.5% | 89.0% | 88.0% (p < 0.001) |
| wanderer | 98.0% | — | 99.0% (โมเดลผิด → จับคนแรกช้าลงเล็กน้อย 26 → 28 วิ) |

ข้อสังเกตที่ควรพูดตรง ๆ ในเล่ม:
- **opponent model ให้ผลมากที่สุด** มากกว่าการวางแผนเสียอีก
- belief + model (ไม่วางแผน) ได้ใกล้เคียงหรือดีกว่า pomcp + model ด้วยซ้ำ (hider 99% vs 96%, collector 39.5% vs 31.5%)
  → การวางแผนช่วยมากที่สุดตอนโมเดลผู้เล่นยังหยาบ; เมื่อโมเดลแม่นแล้ว แค่ "เดินไปที่ที่น่าจะอยู่" ก็พอ
  สาเหตุที่เป็นไปได้: observation ใน POMCP ย่อเหลือแค่ "จับได้/ไม่ได้" ไม่ได้จำลองเสียง
- ผลกับบอทเกินจริงแน่นอน บอทมีพฤติกรรมตายตัว คนจริงคาดเดายากกว่า → ต้องยืนยันด้วย playtest

### 3.4 งบเวลาของ POMCP (anytime)

4 ผู้เล่น: วางแผนเต็ม 200 simulations ใช้ 8–11 ms ต่อครั้ง (เสี่ยงเซิร์ฟเวอร์สะดุด) จึงให้หยุดที่ 4 ms
(อย่างน้อย 50 simulations) — ผลการจับไม่ต่าง: hider 80.4% vs 77.9%, collector 8.3% vs 10.4% (60 คืน)

### 3.5 ความยากตามคืน (บอทเก็บลัง 2 ตัว, ค่าความเร็ว/การได้ยินจริงของเกม) — โอกาสผู้เล่นชนะ

| คืน | belief | pomcp | pomcp + model |
|---|---|---|---|
| 1 | 97% | 89% | 68% |
| 3 | 96% | 84% | 51% |
| 5 | 81% | 73% | 46% |
| 7 | 59% | 60% | 43% |

→ ตาราง story: คืน 1–2 belief, 3–6 pomcp, 7 pomcp + model ("มันเรียนรู้การเดินของคุณแล้ว")

## 4. ระบบหลังบ้าน

```
Roblox server ──POST /v1/nights (batch ตอนจบคืน)──▶ FastAPI ──▶ SQLite / PostgreSQL
      ▲                                               │
      └──GET /v1/params/latest (ตอนเปิดเซิร์ฟเวอร์)──── POST /v1/train (daily job)
```

- ฝึกโมเดล: แบ่ง run 80/20 ด้วย hash ของ run id → ฝึก 80% → ให้คะแนนกับ 20% ที่ไม่เคยเห็น
  → **เปิดใช้เฉพาะเมื่อทำนายดีกว่าโมเดลที่ใช้อยู่** (กันโมเดลแย่หลุดเข้าเกม)
- โค้ดฝึกใน Python เป็น port ของ Luau มี golden test ว่าได้น้ำหนักตรงกับ Luau ถึงทศนิยม 12 ตำแหน่ง
- ความปลอดภัย: API key แยก game/admin (compare แบบ constant-time, key ว่าง = ปิด), จำกัดขนาด body 2 MB,
  validate ทุก field (คืน 1–7, node 0–64, ความยาว trajectory ต้องตรงกับจำนวน tick, ห้ามชื่อผู้เล่น),
  กันข้อมูลซ้ำเมื่อเกมส่งซ้ำ
- ความเป็นส่วนตัว: ไม่ส่ง user id/ชื่อ ผู้เล่นเป็น p1..p4 ภายในรอบ
- ตรวจแล้ว: 22 tests ผ่าน; รันเซิร์ฟเวอร์จริงแล้วส่ง record ที่บันทึกจาก Studio เข้าได้, stats/dashboard ทำงาน
- **ยังไม่ได้ตรวจ:** Roblox → backend ตัวจริง (HttpService ของแมพยังปิด, ต้อง deploy เป็น HTTPS ก่อน), Docker image (Docker Desktop ไม่ได้เปิด)

## 5. ข้อจำกัด (ต้องเขียนในเล่ม)

1. ผลทั้งหมดในหัวข้อ 3 มาจากบอท ไม่ใช่คน
2. z-test ถือว่าผู้เล่นแต่ละคนอิสระกัน แต่ 2 คนในคืนเดียวกันไม่อิสระ และใช้ seed คู่กัน (paired)
   → ควรรายงานเพิ่มด้วยการทดสอบแบบ paired (เช่น McNemar ต่อคืน) หรือ bootstrap ระดับคืน
3. Observation ของ POMCP ย่อเหลือ 2 ค่า (จับได้/ไม่ได้) ไม่มีเสียง → ปีศาจไม่ "หยุดฟังเพื่อหาข้อมูล" จริง ๆ
4. Opponent model ไม่ขึ้นกับตัวผู้เล่น (ทุกคนใช้โมเดลเดียว) ยังไม่ปรับตัวระหว่างเล่น
