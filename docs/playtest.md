# แผน Playtest (M4)

## คำถามวิจัย
ปีศาจที่ติดตามด้วยความเชื่อ (particle filter) + วางแผน (POMCP) + เรียนรู้การเคลื่อนที่ของผู้เล่น (opponent model)
**ท้าทายและน่าเล่นกว่า** ปีศาจแบบกฎหรือไม่ เมื่อเล่นกับคนจริง

## เงื่อนไข (between-subjects ต่อรอบ)
ตั้ง ServerStorage attribute `HunterMode = "experiment"` → ทุกรอบ (7 คืน) สุ่ม 1 เงื่อนไข:
`rule` · `belief` · `pomcp` · `pomcp+model` (บันทึกใน telemetry ช่อง `condition`)
ผู้เล่นไม่รู้ว่าได้เงื่อนไขไหน (blind)

## ผู้เข้าร่วม
- เป้า 15–30 คน (เพื่อน/รุ่นน้อง/ครอบครัว), เล่นเดี่ยวหรือกลุ่ม 2–4 คน, คนละ ~20–30 นาที
- แจ้งก่อนเล่นว่าเก็บข้อมูลการเล่นแบบไม่ระบุตัวตน (ตำแหน่งในบ้าน, ผลแต่ละคืน) และขอความยินยอม
- ผู้เล่นอายุต่ำกว่า 18: ขอความยินยอมจากผู้ปกครอง / ใช้แบบสอบถามที่ไม่เก็บข้อมูลส่วนตัว

## สิ่งที่วัด
| ตัวชี้วัด | ที่มา | เปรียบเทียบ |
|---|---|---|
| อัตราชนะต่อคืน (ผู้เล่น) | telemetry `outcome` | ระหว่างเงื่อนไข, z-test + Wilson CI (`/v1/stats`) |
| จำนวนครั้งล้ม/คืน, เวลาถึงการล้มครั้งแรก | telemetry `events` | ระหว่างเงื่อนไข |
| คืนที่ไปได้ไกลสุดต่อรอบ | telemetry | ระหว่างเงื่อนไข |
| ความแม่นของ opponent model กับคนจริง | `/v1/train` metrics (holdout LL, accuracy) | learned vs uniform |
| เวลาคำนวณของปีศาจ | telemetry `hunter.avgPlanMs / maxPlanMs` | ต้อง ≤ 5 ms |
| ความรู้สึก: ท้าทาย, ปีศาจดู "ฉลาด"/"โกง", สนุก, อยากเล่นอีก | แบบสอบถาม Likert 1–5 หลังเล่น | ระหว่างเงื่อนไข (Mann-Whitney) |

คำถามสำคัญในแบบสอบถาม: "ปีศาจดูเหมือนโกง (มองเห็นเรา) ไหม" — ปีศาจที่ดีควรเก่งแต่ **ไม่รู้สึกว่าโกง**

## ขั้นตอน
1. Deploy backend, ใส่ `TelemetryUrl` + secret, เปิด Allow HTTP Requests, Publish
2. ทดสอบ 1 คืนเอง → ดูว่า `/v1/stats` มีข้อมูลเข้า
3. รอบแรก (สัปดาห์ 1): story mode ให้คนเล่น เพื่อเก็บ trajectory → `POST /v1/train` → ได้โมเดลจากคนจริงตัวแรก
4. รอบสอง (สัปดาห์ 2): experiment mode เก็บผลเทียบ 4 เงื่อนไข + แบบสอบถาม
5. วิเคราะห์จาก `/v1/stats` + export DB, เขียนผลลงเล่ม
